## Implemented authority

`GET /api/cases/:caseId/files/review` returns bounded 50-document pages and a separately selected exact file. A document link can identify an earlier file beyond the first page. Unavailable, purged and archive-only outcomes retain existing individual-download authority. Earlier attachment mirrors are not silently promoted into new records. File names, sizes, upload dates, versions, review instructions and security states are explicit; storage keys and uploader identities are omitted.

`POST /api/cases/:caseId/files/:fileId/review` supports approval, revisions and return to awaiting review. It requires the approved attorney's fresh account/session, raw owner and assignment agreement, funded active document authority, the displayed document/Matter fingerprint, and current scanning. A single transaction writes the Case guard and selected CaseFile, preserving unknown fields and using existing statuses. Completion, withdrawal, assignment and replacement writes conflict with that transaction. No fallback to separate writes or automatic transaction retry exists. The final account check occurs outside the transaction snapshot; it is not an atomic account-deletion transaction.

Revision instructions remain encrypted using the existing field convention. Explicit revision-of IDs, source versions and request times are preserved. Approval applies to the document actually reviewed. Earlier revision records retain their own status; existing paralegal reads derive resolution from explicit lineage. The new Files surface currently links to the earlier document; complete forward lineage/replacement-history presentation remains in the following file work.

Existing scan persistence now matches the scanned file's stored reference and version. A result for an earlier object cannot mark a replacement clean. Individual downloads also re-read the fresh attorney account before and after storage, including token/session revocation. Native PDF preview uses the same guarded endpoint with an explicit PDF-only inline option; all other MIME types reject that option. Ordinary downloads retain attachment/octet-stream headers. PDF viewing has its own audit action. The shared site's frame policy remains unchanged.

## Interface

Document selection opens its details. Approval/revision/reopening has a named, versioned confirmation with the consequential effect. Instructions for different documents are retained separately in account-scoped tab memory. Lost/conflicting decisions require a fresh saved-status check; no request is automatically repeated and a matching fresh status is not described as proof of an exact earlier request.

Text preview inserts text nodes, with an explicit 1 MB preview limit and full-download action. Image previews use protected bytes and revoked object URLs. PDF preview uses a same-origin protected frame and a native-viewer capability fallback. Closing/navigating removes the frame. File access/account checks run at the endpoint; the client verifies the account before requesting the frame and again after its load. Security errors, missing/replaced objects and aborted transfers never report a successful download. A stale file selection stays disabled until the file list is refreshed.

The common Matter workspace owns realtime/poll cleanup. Background file reconciliation preserves the loaded extent and does not replace active revision instructions. During explicit reads and decisions, visible controls reflect their unavailability instead of silently ignoring clicks. Full final attorney editorial/layout and real-device/native-PDF acceptance remain later review gates.
