# Attorney Matter calendar

Calendar entries are now implemented in Activity alongside the separately labeled Matter deadline and recorded status/activity dates. The source remains Event. Existing owner-only calendar access is preserved, including entries whose retained visibility metadata says case_team or public; those hints do not establish actual sharing. Calendar actions do not change Case.deadlineDate.

## Contract and preservation

GET `/api/events/matters/:caseId/review` supplies 50 entries per page, stable start/_id continuation, real filtered totals, exact entry selection and saved-action recovery. It includes the signed-in owner and Matter revision, safe recorded attendee/reminder metadata and explicit missing selections. Event gains the owner/caseId/start/_id index. UTC date-range filters are labeled accordingly; entries display their recorded time zone.

POST `/api/events/matters/:caseId/reviewed-action` implements create, partial update, remove, attendee append and reminder append. Fresh account/Matter checks, the displayed entry revision and raw-record guards bind the action. Event and Case guards plus an existing AuditLog record commit in one transaction. The deterministic audit ID and payload fingerprint identify the exact request without adding a model or duplicating calendar notes in the audit. Repeated requests cannot create duplicate entries, change their original payload, or recreate a later-removed entry. Lost acknowledgements are checked before an explicit retry. Transactions have no standalone fallback or automatic retry.

Configured Event/AuditLog initialization finishes before these reads/actions so first-use transactions do not race the models' collection/index setup. Raw selective updates preserve unknown fields, legacy string references, source, visibility, repeat rule, color, original instants and nested attendee/reminder metadata. Attendee records retain response state; adding one does not send an invitation. Reminder actions record settings and do not claim delivery. Existing recurrence metadata is retained and shown without inventing expanded occurrences.

New all-day entries use the existing noon-UTC business-date convention; an untouched earlier all-day entry retains its original instants. Timed entries resolve the chosen wall-clock date/time in its IANA zone. Nonexistent daylight-saving times are rejected, and a repeated time requires an explicit occurrence. Editing only notes does not round away original seconds or rewrite the end time. Pending changes and action IDs stay in tab memory, survive internal navigation and clear on account/Matter access loss. The existing Matter poll owns refresh; no additional stream is created.
