# Invitation actions — local workflow acceptance

September 7, 2026. The active instruction is to continue until the full attorney experience is ready for final owner review. This slice is part of that work, not a final handoff.

Checkpoint: `backend/backups/attorney-v2-phase5-invitation-actions-start/`, with 1,867 initial file hashes and exact baselines for the bounded owned paths. The preceding pre-engagement candidate and its accepted source archive are retained separately.

The candidate page now contains paged Matter selection, invitation and amount review, explicit send confirmation, current response status, and links to the corresponding applications and invitation history. The new read endpoints are `GET /api/cases/invitation-options/:paralegalId` and `GET /api/cases/:caseId/invitation-review/:paralegalId`. Sending uses the existing invitation endpoints with an exact reviewed revision and owner. Current clients retain their existing send contract.

The reviewed send checks current account/profile/block/ownership and existing invitation policy, then atomically preserves the reviewed amount, invitation records and retained revision. A pending invitation held only in earlier fields is retained when another invitation is sent. Earlier text identifiers and unknown evidence are preserved. The legacy send path also guards its loaded amount, lock and revision and cannot overwrite a newer lock or race past an acquired hire claim. Sending has no hiring or funding effect. Existing development-only payout exceptions remain confined to the existing route configuration; no new production exception is introduced.

The UI never automatically retries an invitation. An interrupted response leads to a read of actual saved status without a claim that this proves the exact original request succeeded. Confirmation metadata is checked against the chosen paralegal, reviewed revision and amount. Unsure actions remain only in tab memory and clear on account protection.

The attorney can send or resend where the existing policy permits. Accepting, declining and revoking an accepted invitation belong to the paralegal. The paralegal-only revoke endpoint does not create an attorney revoke control. A revoked accepted invitation remains a declined invitation with a withdrawn application under the existing contract.

Replacement-work review distinguishes the original recorded amount from the remaining Matter amount. A changed or unsettled balance prevents the old reviewed invitation. Availability remains profile context; the existing invitation policy does not make a general availability label an independent permission. The current account, payout setup, block, assignment, open/replacement state and invitation records determine eligibility.
