# Attorney dispute review and discussion

Local implementation, September 8, 2026. This slice implements dispute history, exact earlier discussion links, comments and reviewed opening from the Matter’s Financials tab. It does not complete the full attorney experience or enable release.

## Authority and behavior

`routes/disputes.js` remains the authority for existing roles, funded-work eligibility, withdrawal windows, shared notifications and administrator settlement. New attorney review/action routes use `services/attorneyDisputes.js`; existing role consumers retain their response contracts. The older participant reader now independently checks the actual current/withdrawn participant and excludes unknown private fields. A pending invitation alone previously passed the shared read middleware and could expose dispute records; the reader now denies that access. Administrators retain their private notes and existing controls.

The attorney service checks the approved current account, verified token version, active session and fresh Matter ownership. It preserves ObjectId/string aliases, earlier `_id`-only disputes, opaque dispute references, absent dates and unknown stored metadata. It exposes only explicit public fields, with opaque keyed review revisions so private administrator notes cannot be recovered from a predictable revision hash. Invalid or duplicate earlier dispute identifiers cannot accept comments.

History and discussion each page 25 records with actual totals. An exact older dispute/comment can be opened without loading every page. A changed order invalidates a cursor; a changed discussion invalidates an earlier confirmation. Missing records, unavailable reads and an empty successful history remain distinct. Quiet Matter refreshes preserve loaded pages, focus and drafts; changed records require an explicit refresh.

Opening requires real disagreement details, the reviewed Matter revision and an explicit confirmation of shared visibility and paused work. No amount is invented for attorney requests. Opening changes the existing Matter/dispute fields and existing administrator-review deadline; it does not initiate a transfer or refund. The backend permits funded `completed` records as well as active/paused work, while the old page hid the control on completed records. This implementation follows the backend’s existing funded-work rule and adds no new legal deadline. The withdrawn paralegal’s review window and expired-window restrictions remain authoritative.

A UUID binds an action to its original account, Matter, operation, target and text. The Case change and exact AuditLog outcome commit together. Concurrent opening, changed inputs and stale discussions cannot overwrite newer decisions. A lost commit acknowledgement can recover the recorded outcome. A request that discovers another simultaneous copy’s committed result does not publish a second notification set. Transactions have no fallback to separate writes and no automatic resubmission. An explicitly retried unrecorded request retains its original UUID.

Comments retain the existing permission to discuss an earlier resolved or rejected dispute. Matching administrator settlement amounts are labeled as a recorded decision, with a link to the Matter receipt. That decision does not claim a completed transfer/refund, and private administrator notes/provider identifiers are absent. Administrative settlement, rejection and private-note controls remain administrator-only. Matter flags and resolution requests belong to the separate existing moderation surface; the final P4/P8 inventory remains open.

Drafts and pending requests stay in tab memory, survive Matter-tab changes, and clear on account/access loss. Stop waiting preserves an uncertain request for a read. Reads and writes check the current owner before and after the API operation. The section uses the existing Matter stream and fallback; it adds no independent stream or polling interval.
