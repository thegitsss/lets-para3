# Payments page and billing handoff

Locally verified under `backend/backups/attorney-v2-phase8-payments-page-start/` (2,701 initial hashes; 16 owned paths). This replaces the Payments fallback with an actual saved-card section, compact saved hiring return, payment-record list, exact Matter/receipt links and guarded billing handoff. Existing card setup remains the actual provider form; its success wording now works without a pending hire.

GET `/api/payments/attorney-records` is read-only. It does not call the older pending-escrow GET, which can create checkout sessions. Lists have 50-row keyset pages, full filtered counts, literal title search, raw ObjectId/string ownership, exact Matter selection beyond the current page and fresh account/record checks. Displayed Matter amounts remain exact cents before attorney fees; they are not represented as cash balances or total spend. Invalid amounts/currency need review. Funding, release, payout failure/reversal and withdrawal decisions keep separate labels; updatedAt is not invented as a funding/release date. Individual receipts retain the existing stronger provider verification.

POST `/api/payments/portal/attorney` requires the current approved account, existing saved customer, exact request ID and fixed V2 return. It uses a provider idempotency key, no automatic network retries and fresh account/customer checks around the provider calls. Only the exact HTTPS billing.stripe.com session URL is accepted. No checkout, charge or new customer is created by this endpoint. Existing portal callers keep their previous route.

Earlier entries in `Case.withdrawalHistory` keep the Matter in the withdrawal filter after reassignment clears its current withdrawn-paralegal fields. The list records their count and preserves full/partial/zero decision types; complete earlier decision detail and receipt selection remain part of the next financial-history work. Counts and listed amounts are not a reconciled account balance.
